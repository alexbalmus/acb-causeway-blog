Experimenting with Apache Causeway by creating a blogging platform.
https://causeway.apache.org

== Requirements

Tested with:

- Open JDK 25 (should work with 21)
- Apache Maven 3.9.15
- NodeJS v24.14.0

== Building

mvn package

== Running

mvn spring-boot:run

== JVM Options

PROTOTYPING=false // clear the prototyping actions from the UI

== Spring profiles

- "Dev": enables automatic content generation for testing purposes
- "Ai": enables Spring Ai features like automatic Ai content generation (when paired with "Dev" profile) or Ai moderation

== Spring AI

Make sure SPRING_AI_OPENAI_API_KEY is set for your environment

== Running with Spring profiles and JVM options

mvn spring-boot:run -Dspring-boot.run.profiles=Dev -Dspring-boot.run.jvmArguments="-DPROTOTYPING=false"

or with Spring Ai:

mvn spring-boot:run -Dspring-boot.run.profiles=Dev,Ai -Dspring-boot.run.jvmArguments="-DPROTOTYPING=false"


== Server-rendered blog client

Open http://localhost:8080/blog after starting the application. This client uses
Spring MVC, JTE templates, HTMX and Bootstrap Litera. All existing blogs and posts
are publicly readable and searchable here. Click Edit to sign in with an existing
account and return to the editor. Only the owner can change a blog or its posts.
My Blogs includes blog creation and handle management.

The client shares the server-side session with Angular and Wicket. Use the same
hostname in each client. Signing out invalidates the shared session. REST and
GraphQL still require authentication; this does not expose those APIs publicly.

HTMX updates forms and articles without a full page reload. Normal links and
forms also work without JavaScript. JavaScript dependencies are pinned WebJars
served locally; building this client requires Maven only, with no Node build.

`mvn package` compiles the templates into the executable JAR. For template
reloading, run from the project directory with the additional `jte-dev` profile:

[source,shell]
----
mvn spring-boot:run -Dspring-boot.run.profiles=Dev,jte-dev
----

Templates live in `src/main/jte/blog`; Java controllers and presentation services
live in `webapp.blog`. Existing Causeway actions, mixins and property rules handle
mutations through wrappers. JTE view models contain presentation data, not entities.

New-client picture uploads default to 5 MiB and 20 megapixels. Configure
`acb.blog.max-image-bytes` and `acb.blog.max-image-pixels` to change these limits;
also adjust `spring.servlet.multipart.max-file-size` and `max-request-size` if
raising the byte limit. Invalid images are rejected before persistence.

No publication flag or draft state is introduced: creating a post makes it
readable immediately. Account provisioning and the existing database configuration
are unchanged. See `SECURITY.md` for account setup.

== Angular web client

The `webclient/` folder contains an Angular frontend that consumes the
Restful Objects API auto-generated by Causeway under `/restful`, providing
the same functionality as the default Wicket UI (blogs, posts, pictures,
handles, ownership rules and validation). See `webclient/README.md` for
details.

To run it against a locally running backend:

  cd webclient
  npm install
  npm start        # serves http://localhost:4200, proxying /restful to :8080
